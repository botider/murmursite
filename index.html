深入淺出 Copilot Subagent：擺脫 Context 泥沼

在這篇文章中，我想探討以下幾個問題：

  • 為什麼我們需要 Subagent？
  • 在真實的開發流程中如何應用？
  • 它與 Skill 有什麼本質上的區別？

為什麼需要 Subagent？

在 2025 年 10 月，GitHub Copilot for VS Code 將 “chatmodes” 升級為 “agents”，並帶來了強大的 “subagent” 能力。這讓主 Agent 能夠啟動「另一個擁有乾淨 Context、甚至使用不同模型的獨立 Agent」。

單一 Agent 最大的痛點在於：當對話時間拉長，Context 累積過多雜訊後，回應品質會顯著下降（變笨）。

Subagent 的出現解決了這個問題：

  1. 乾淨的上下文 (Clean Context)：每次任務都從零開始，避免歷史包袱。
  2. 非阻塞執行 (Non-blocking)：多工處理時，Subagent 在背景平行運作，不會卡住你的主對話框。
  3. 計畫委派 (Delegation)：在 Plan Mode 下，主 Agent 可以將拆解後的步驟交由 Subagent 執行。

實際應用 (Real Dev Scenario)

1. 設定 (Setup)

首先，我們需要在 .github/agents/ 目錄下定義 Agent：

  • Scope：設定是個人專用還是專案共享。
  • Description：這是關鍵。你需要清楚描述這個 Agent 能做什麼 以及 何時該用。（例如：當你需要修改 C# 程式碼時… 請使用此 Agent）。
  • Tools：定義這個 Subagent 可調用的指令、MCP 或 Skill。
